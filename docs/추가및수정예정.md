# 추가 및 수정 예정 목록

지금까지 진행하면서 **나중에 정하거나, 수정하거나, 추가하기로 한 내용**을 모은다.
하드웨어가 없어 확인하지 못한 항목은 `docs/미검증.md`에 따로 있다 (여기서는 "할 일"만 다룬다).

- 마지막 갱신: 2026-10-11 (3단계 완료 시점)
- 상태: ⬜ 예정 / 🔄 진행 중 / ✅ 완료 / ✖ 하지 않기로 함
- "결정" 열: 사용자가 정한 내용인지(사용자), 진행 중 제안된 개선 후보인지(제안)

## 1. 사용자가 정한 예정 사항

| 상태 | 내용 | 언제·조건 | 관련 위치 | 바꿀 때 할 일 |
|---|---|---|---|---|
| ⬜ | **기말 업무 규칙 추가** (입고·출고, 상품 정보 등) | 기말고사 즈음 | `barcode_system/store.py` (스키마 버전 1) | 새 테이블 추가 시 `SCHEMA_VERSION`을 2로 올리고 이전(migration) 코드 작성. 지금은 스캔 원본만 기록 |
| ⬜ | **바코드가 찍힌 물품을 관리하는 웹 페이지** | 기말 또는 이후 | `data/barcodes.db` (SQLite, WAL) | DB를 그대로 읽으면 된다 (WAL이라 db-writer와 동시 사용 가능). 쓰기 기능을 넣으면 db-writer와의 잠금·스키마를 함께 설계 |
| ⬜ | **라즈베리파이 OS 결정** (지금은 Bookworm·Python 3.11로 가정) | 파이 준비 시 | `requirements-pi.txt`, `requirements-dev.txt`, Windows Python 3.11 | Trixie(Python 3.13)로 정하면: Windows Python 버전 변경, apt OpenCV 4.10(cv2.barcode 포함)·paho 2.x 사용 가능 → requirements-pi.txt 단순화, numpy<2·OpenCV 4.11 고정 재검토 |
| ⬜ | **브로커 영속성 수준 조정 가능성** (지금: 변경할 때마다 저장) | SD카드 부하가 걱정될 때 | `mosquitto/pi/barcode.conf` `autosave_interval 1` | 값을 키우면(예: 100) 부하는 줄지만 브로커 강제 종료 시 db-writer 몫 메시지 유실 가능. `tests/test_pipeline.py`가 이 파일 값으로 검증하므로 바꾼 뒤 테스트 실행 |
| ⬜ | **토픽에 `{site}` 단계 추가** (`warehouse/{site}/scanner/...`) | 창고가 여러 곳이 되면, 사용자가 요청 시 | `barcode_system/messages.py` `TOPIC_ROOT`, `mosquitto/pi/acl`, `subscriber.py`, `serial_bridge.py` | 토픽 구조·ACL·구독 필터를 함께 변경, 메시지에 site 필드 추가 검토 |
| ⬜ | **TLS 암호화** | 필요하다고 판단될 때 | `mosquitto/pi/barcode.conf`, 각 앱의 MQTT 연결 | 8883 리스너 + 인증서, paho `tls_set()`, 설정 파일에 CA 경로 추가 |
| ⬜ | **UNO 보드 확정** (CH340 또는 CH341 호환보드) | 보드 구입 시 | `serial_bridge.py` `USB_IDS` (둘 다 등록됨) | 다른 칩(예: CP2102)이면 VID:PID 추가. 보드가 정해지면 `docs/미검증.md` 3단계 항목 확인 |
| ⬜ | **부품 사양에 맞춘 UNO 설정** (LCD 주소, 부저 종류, 핀) | 부품 연결 시 | `arduino/uno_display/pins.h` | 능동 부저면 `BUZZER_PASSIVE 0`, 핀 변경 시 README 배선표도 수정 |
| ⬜ | **실제 카메라 실측** (웹캠·Pi 카메라) | 웹캠·카메라 준비 시 | `docs/미검증.md` 1단계 | 결과에 따라 `--cooldown`, `--confirm`, 해상도, `--engine` 기본값 조정 |
| ⬜ | **라즈베리파이 연동** (SSH 접속, 실제 배치) | 파이 준비 시 (SSH 가능 여부는 그때 확인) | `mosquitto/pi/setup_broker.sh`, `deploy/install_services.sh` | 브로커 설치 → 설정 파일·비밀번호 파일 작성 → 서비스 설치 순서 |
| ✅ | 스캔 기록 삭제 기능 (무기한 보관 + 수동 삭제) | 2단계에서 완료 | `barcode_system/db_tool.py delete` | 자동 정리(보관 기간)는 넣지 않기로 함 |

## 2. 검토 후보 (진행 중 제안된 개선, 필요할 때 결정)

| 상태 | 내용 | 이유 | 관련 위치 |
|---|---|---|---|
| ⬜ | MQTT 5로 전환해 ACL 거부를 발행 측에서 감지 | MQTT 3.1.1은 ACL로 거부된 발행도 PUBACK을 보내 스캐너가 성공으로 기록함 (지금은 사용자 이름 ≠ scanner_id면 경고만) | `mqtt_compat.py`, `publisher.py` (paho 1.x는 PUBACK 사유 코드를 주지 않아 2.x 전용이 됨) |
| ⬜ | ACL을 스캐너별 `user` 블록으로 바꾸기 | `pattern` 규칙은 db-writer·monitor·uno-bridge에도 적용됨 (지금은 db-writer가 토픽·내용 scanner_id 불일치를 거부해 보완) | `mosquitto/pi/acl`, `setup_broker.sh` |
| ⬜ | 시리얼 속도를 57600bps로 낮추기 | CH340 보드에서 115200bps 통신 오류가 잦을 경우 | `pins.h` `SERIAL_BAUD` + `config/uno_bridge.ini` `baud` (둘 다 같이) |
| ⬜ | UNO가 기억하는 lost 스캐너 수 늘리기 (지금 4개) | 스캐너가 5대 이상이 되면 | `pins.h` `MAX_SCANNERS` (SRAM 여유 확인) |
| ⬜ | 긴 바코드 값 LCD 표시 방식 (지금: 15자 + `~`) | 16자를 넘는 위치·팔레트 코드를 많이 쓰면 | `uno_display.ino` `copyFit` (스크롤 또는 뒷부분 표시) |
| ⬜ | NTP 동기화 여부를 메시지에 표시 | 파이에 RTC가 없어 부팅 직후 스캔 시각이 틀릴 수 있음 (지금은 DB에 수신 시각을 함께 저장) | `messages.py`, `store.py` |
| ⬜ | outbox를 새로 만들 때 seq가 1부터 다시 시작하는 문제 | 누락 구간 조회(`db_tool gaps`)가 부정확해질 수 있음 | `outbox.py`, `store.py gaps()` |
| ⬜ | `max_queued_messages`(100000) 초과 대비 | db-writer가 아주 오래 꺼져 있으면 브로커가 이후 메시지를 버림 | `mosquitto/pi/barcode.conf`, db-writer 감시(systemd 재시작으로 일부 대응) |
